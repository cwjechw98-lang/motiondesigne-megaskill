# Интеграция под конкретный харнесс

Цель — помочь пользоваться библиотекой в текущей среде, а не переделать среду под библиотеку. Сам навык работает без панели. Интеграция — отдельная необязательная задача, которую запускают по запросу пользователя или после явного согласования предложения агента.

## 1. Сначала наблюдение, потом обещание

Составь короткую карту возможностей, загружая только относящиеся к задаче документы:

| Возможность | Как подтвердить | Если нет |
|---|---|---|
| Загрузка навыков | каталог/команда/документация текущего агента | дать ручную инструкцию, не менять глобальный prompt |
| Показ изображений | открыть один локальный тестовый файл | текстовый каталог с путями/ссылками |
| HTML-превью | проверить скрипт и CSS в штатном viewer | открыть галерею обычным браузером |
| Постоянная панель | документированный extension API, реальная проба | не рисовать обещанную панель в конфиге наугад |
| Вставка в черновик | подтверждённый API редактора + тест | копирование промпта |
| Рендер видео | проверить существующий рендерер/выходной файл | динамическая проба и честный статус |

Не делай вывод из названия API. Наличие iframe не гарантирует выполнение скриптов. Наличие сервера файлов не означает разрешения CSP. Наличие общего main/sidebar-слота не делает его привязанным к режиму. Проверь область: чат, рабочая папка, режим или весь GUI.

## 2. Лестница интеграции

Остановись на первом уровне, который решает задачу человека.

**A. Без интеграции.** Агент читает каталог, предлагает идеи и создаёт работу. Пользователь открывает `gallery.html` в браузере и копирует промпт. Самый переносимый вариант; никакого фонового процесса.

**B. Штатный просмотр артефакта.** Используй существующий viewer или attachment-механизм. Проверь, что изображения, CSS и JavaScript действительно доступны. Если viewer запрещает скрипты, предложи копирование/обычный браузер, а не ослабление CSP.

**C. Пользовательская команда или действие.** Документированный механизм открывает библиотеку или выводит каталог. Команда не выполняет произвольный код из промпта и не отправляет сообщение без нажатия пользователя.

**D. Пользовательский плагин/панель.** Только если нужен постоянный доступ и текущая среда поддерживает расширения. Сам адаптер хранится вне пакета приложения; использует документированный API. Данные берёт из навыка по относительному/обнаруженному пути. Ни каталог, ни промпты не нужно жёстко вшивать в shell.

Если расширения нет, не переходи автоматически к патчу установочного каталога. Скажи: «Здесь безопаснее отдельная галерея; встроенная панель потребует неподдерживаемого изменения».

## 3. Проверка адаптера

Перед кодом зафиксируй: версию харнесса, фактический контракт API, область действия, способ выключения и альтернативу. Не называй это гарантированной совместимостью без запуска.

Проверь:
- Адаптер появляется только там, где обещано; не дублируется между чатами.
- Переключение режима/чата и закрытие панели освобождают подписки.
- Каталог загружается из каталога навыка, а не из текущей cwd.
- Выбор карточки меняет **черновик**, не отправляет запрос и не запускает рендер.
- Ошибка адаптера не ломает запуск самого агента и не уничтожает настройки.
- После перезагрузки/перезапуска дополнение находится штатным механизмом.
- При несовместимости API доступна обычная галерея.

Протокол необязательного iframe-адаптера описан в `../docs/integration-contract.md`. Нужны проверка origin/source/schema и ограничение размера сообщения. Не доверяй HTML/сообщениям из чужих страниц. Не выдавай iframe лишние полномочия ради кнопки копирования.

## 4. Обновления без хрупкого патчинга

Разделяй три слоя:

1. **Контент навыка:** SKILL.md, references, catalog, assets, gallery. Это переносимый пользовательский пакет.
2. **Данные пользователя:** избранное, свои рецепты, настройки интеграции. Храни рядом с пакетом или в штатном пользовательском хранилище, не внутри перезаписываемого релиза. Не записывай туда секреты.
3. **Адаптер:** необязательный тонкий мост к документированному API харнесса. Может потребовать обновления при изменении API, не должен быть единственным доступом к контенту.

Не редактируй `node_modules`, web bundles, app resources, глобальные системные инструкции и vendor-файлы. Переустановка/обновление приложения обычно не затрагивает отдельный пользовательский пакет, но поведение конкретного установщика проверяется, а не гарантируется. При смене API отключай адаптер и сохраняй fallback — не выдавай поломку адаптера за потерю навыка.

## 5. Безопасная установка и замена

Путь пользовательских навыков узнавай из документации текущего агента. Встроенный `scripts/install.mjs` требует явный целевой каталог навыка, работает локально и не правит shell. Сначала `--dry-run`. Существующий каталог без `--replace` не трогается; замена должна создать резервную копию. Проверь реальные флаги через `--help` перед применением.

Обновление скачивает пользователь в штатном порядке. Перед заменой сравни изменения, проверь происхождение, сохрани пользовательские дополнения и запусти проверку комплекта. Никаких скрытых auto-update, автозапуска при логине или регистрации платного сервиса.

## 6. Итог пользователю

Скажи простыми словами: какой вариант выбран и почему; как открыть библиотеку; как получить помощь агента; что не менялось; как отключить интеграцию; что проверено и что требует будущей проверки. Не проси человека решать, в какой внутренний realm монтировать сервис.
